# 回答思维导图与双击识别

日期：2026-10-12。Linux x86_64，Bevy 0.19.1。

## 行为

新建的画布文字任务（无外部工程、无旧 Agent 投影）把回答列表投影成多级文本节点，直接连接原始问题。规划仍参与后台调度和历史保存，不产生“任务规划”画布框。旧分组不自动删除或转换。

正文仍使用 `Proposal.summary`，无需新增 `.mio` schema。画布绑定新增可缺省的 `answer_maps`，记录 Run ID 和生成节点 ID；旧绑定继续可读。节点可编辑，刷新不覆盖编辑、不重建删除节点；选择子节点可追溯到其 Run 并用于 Skill 来源选择。每次新 Run 生成一棵新树，不改写之前结果。

回答采用两空格缩进的 Markdown 列表，一行一个知识点。非列表旧正文保留为平级文本，不推测不存在的层级。投影限制为单次回答最多 256 节点、8 层缩进，超限明确报错并保留完整运行记录；此限制与 Agent 数量无关。

双击识别由 300 毫秒放宽到 500 毫秒，按下期间漂移容差由 5 增至 8 个逻辑像素。保留导航、拖动、占用区域和 UI 捕获的取消规则；尚未进行实体触控板验收，不代表排除了所有偶发输入问题。

- 双击相关测试 9 项通过，覆盖 450 毫秒第二次点击、6 像素漂移、真实拖动、相机变化、UI 捕获及命中边线。
- 协作测试覆盖父子层级、输入直接连线、子节点来源、保存重开、人工编辑及删除后刷新。
- 使用本机已配置 Pi / DeepSeek 实际请求“什么是 Git”，返回合法 JSON，其 summary 是五个主题及各自子节点的缩进列表。该调用验证输出结构，不代表内容逐句合规或执行过代码工具。
- 全 workspace 测试：321 项通过、27 项忽略（包括当前工作区的 SQLite 存储变更，不将这些变更归属于本次提交）。
- `cargo fmt --all --check`、release workspace Clippy（warnings 为错误）及 release 构建通过。
- 将用户提供的 Git 层级作为固定输入，生成 29 个节点、28 条连线；Linux Xvfb / Vulkan 软件渲染截图确认四级层次、原问题直接连接五个主题，没有规划框或回答外框。此图验证投影与布局，正文来自用户示例，不冒充模型实际生成结果。
