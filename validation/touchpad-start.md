# 触控板起手输入修复

2026-10-12。用户反馈双指平移与缩放偶发起手失灵。

代码检查发现两项可复现的输入丢失：

- 画布导航使用通用 `Editor.capture`，包含界面输入框的键盘焦点。即使指针在画布上，协作输入框保留焦点也会拦截平移和捏合。新增独立导航捕获状态；键盘命令仍受焦点保护，导航只受指针占用、实际节点编辑及模态状态等约束。图片缩放仍独占其输入，避免同时移动画布。
- 原生 PinchGesture 的 Started 分支只记锚点，丢弃该事件携带的缩放量；现在第一段也围绕同一锚点应用。

回归测试新增“仅键盘焦点存在时仍能平移、带非零增量的捏合开始立即缩放”，检查相机实际投影与锚点位置。已有多 DPI、捕获/失焦清空、取消后拒绝残余事件、滚轮平滑和相机更新测试继续运行。

验证命令：`cargo fmt --all --check`、`cargo test --release --workspace --locked`、`cargo clippy --release --workspace --all-targets --locked -- -D warnings`、`cargo build --release --locked`。

结果：308 项通过，27 项忽略，0 项失败；格式与 Clippy 检查通过。测试在共享工作区执行，其他会话的改动不纳入本次提交。

范围限制：本轮通过合成 Bevy / winit 事件验证输入处理，没有连接用户的实体触控板，未测量硬件输入延迟或帧耗时；这两项修复不能证明所有驱动/平台上的偶发失灵已经消除。
