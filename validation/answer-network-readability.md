# 密集回答的关系网可读性

2026-10-12，Linux，Bevy 0.19.1。

用户截图对应的真实“讲解美国历史”输出有 16 个节点、22 条模型关系，15 个节点未指定分组。旧投影又追加了 15 条原问题连线，总计 37 条。长概述被用作分组标题，进一步拉宽布局。

本次调整：

- 原问题只连接一个入口。
- 无歧义且不成环的“包含阶段/包含主题”转为分组；其它语义关系保留。
- 长分组标题拆成简短标题和完整正文子节点；散落的其它根节点收纳到“相关要点”。不删减原回答文字。
- 移除模型输出的界面操作边；时间顺序仍有箭头，省略重复标签。
- 扩大正文宽度、组内间距和跨组通道，提示模型按主题组织内容并控制关系密度。

回归使用此次实际回答作为 fixture，检查正文保留、一个入口边、短组标题、正文节点互不重叠及归属转换不成环。原始运行历史不修改，既有用户画布不自动覆盖。本次不是全局最优图布局算法，任意复杂关系仍可能交叉。

[重排截图](answer-network-readability.png)：真实旧回答投影为 20 个节点、15 条连线，包含新增分组与正文子节点。Xvfb / Vulkan 软件渲染检查确认叶节点互不重叠、跨组关系从左右端口进出；全图缩放后仍需放大阅读长正文。

另行通过本机 Pi / DeepSeek 实际请求同一问题，返回 28 个节点、18 条语义边，顶层为“殖民地时期、独立与建国、现代美国”三个主题组。该调用验证结构改善，不将模型的全部历史表述视为经过事实核查。

共享工作区最终单元测试 326 项通过、27 项忽略，文档测试被同时写入的缺失 `delegation` 模块打断。安装验证改在仅含已提交内容的独立源码快照中进行，避免包含其他会话未完成的改动。

独立快照验证：`cargo fmt --all --check`、`cargo test --release --workspace --locked`（325 通过、27 忽略，包含文档测试阶段）、`cargo clippy --release --workspace --all-targets --locked -- -D warnings` 均通过。与共享工作区的测试数量差异来自排除其他会话的未提交改动。

独立快照 release 构建完成，通过 Linux 安装器替换本机 `~/.local/bin/graplu`，逐字节比对安装文件与验证二进制一致。原二进制备份到 `~/.local/share/ravomi/backups/readable-layout-20261012/`；未关闭用户正在编辑的窗口。
